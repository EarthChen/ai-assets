# 前端接口文档方法

完整示例随包自带：[../examples/api-doc.md](../examples/api-doc.md)。

读者是前端。目标：前端只看本文档就能对接——每个接口有入参解释、入参样例、出参解释、出参样例。与后门/接口模拟文档（读者 QA，见 [backdoor-bsh-doc.md](backdoor-bsh-doc.md)）分开成文。

## 写前确认

| 项 | 默认 | 说明 |
|---|---|---|
| 范围 | 用户指定的接口类；未指定时取 diff 中新增或修改的 `facade/external` 接口 | 一份文档对应一个接口类 |
| 调用地址 | 只写 `@path` | 写完整 URL 或 curl 时，网关域名由用户提供 |
| 鉴权 | 不写 | 代码看不出来时列入待确认项 |

读者或地址方式不明确时先问。

## 取材步骤

每条事实取自代码或依赖 jar；DTO 注释与实现不一致时以实现为准，并告诉用户注释需要修正。

1. **接口与 path**：接口类每个方法的 Javadoc `@path` 和注释，作为总览表与小节标题。
2. **入参**：请求类字段与注释；公共父类（如 `ClientCommonReq`）在外部 jar 中，用 `javap -p` 列字段，写明哪些字段由网关 header 填充。
3. **出参外层**：`DataResponse` / `CommonResponse` 用 `javap -p` 确认字段（`ec`、`em`、`traceId`、`data`）。成功 `ec` 取 `build(T)` 的实现（`javap -c`），不凭印象写。
4. **序列化**：出参类上的 `@JsonInclude(NON_NULL)` 决定 null 字段不下发；文档统一写"缺失"。
5. **校验与错误码**：逐条读实现类与下游查询服务的 `throw new BusinessCheckException(...)`，每个错误码列出全部触发条件。错误码数值：
   - 本工程枚举直接读源码；
   - 公共 `EcInfo` 从**工程实际依赖版本**的 jar 读：`mvn -q -o -pl <service> help:evaluate -Dexpression=<版本属性> -DforceStdout` 得版本，再 `javap -c` 看常量。`~/.m2` 里的其他版本（如 `*-SNAPSHOT`）数值可能不同，不用。
   - 异常转响应的切面（如 `facade/external` 的 `@Around`）确认 `em` 的来源（错误码多语言文案）与未预期异常的错误码。
6. **默认值规则**：读 `resolve*` / `default*` 方法，把"不传时取什么"写进入参表的说明列。
7. **枚举取值**：状态、赛段码、分区、板块码等从枚举类与编码类读取，写进"枚举取值"表。
8. **场景分支**：神秘人、加载超时、私密房等分支从行装配代码读取，每个出参类型给一张"场景 | 返回 | 前端展示"表。spec 与实现不一致时（如"只返回有数据的板块"在未开始时返回全部）以实现为准。

## 文档结构

```
# <主题>前端接口文档
## 目的（一两行：来源接口类、服务端只返回数据与状态）
## 一、接口总览（表：# | 接口（锚点链接）| path | 分类 | 说明）+ 调用顺序一句话
## 二、通用约定
### 公共入参（header）
### 出参外层（JSON + 字段表 + NON_NULL 说明）
### 错误码（表：ec | 含义 | 触发条件）+ 错误样例
### 枚举取值（表）
## 三、接口详情
### <#>. <方法名>（<中文名>）
path / 入参（字段 | 类型 | 必填 | 说明）/ 入参样例 / 出参（字段 | 类型 | 说明）/ 出参样例
## 四、公共类型（被多个接口引用的嵌套 DTO：字段表 + 场景表）
## 五、前端注意事项（表：场景 | 处理）
```

写作规则：

- 主体用表格；每个接口小节固定四块：入参表、入参样例、出参表、出参样例。
- 同类接口（如多个赛事的"活动信息"）第一个写完整字段表，其余只列差异字段并链接到第一个；样例每个接口都写完整 JSON。
- 嵌套 DTO 被两个以上接口引用时放"公共类型"，接口出参表里用锚点链接。
- 入参只有 header 字段时，入参样例写 `{}` 并说明。
- 样例覆盖不同场景：进行中 / 未开始、上榜 / 未上榜、无参赛实体、神秘人、私密房等，每个接口选一个不同场景，标题括注场景。
- 样例中出现的字段必须是该场景下代码会返回的字段（如某状态提前返回时仍已赋值的字段）；值为示例值，开头声明。
- 错误样例的 `em` 写占位"<ec 的多语言提示>"，不编文案。

## 交付前自查

- 9 类事实（path、入参、header 字段、出参外层、错误码数值与触发条件、默认值、枚举、场景分支、序列化）都有代码或 jar 出处。
- 所有 ` ```json ` 块能被 `json.loads` 解析（Python 提取后逐块校验）。
- 锚点链接与标题一致（GitHub slug：小写、去标点、空格转 `-`）。
- 发现的 DTO 注释与实现不一致项，向用户列出。
